# 相册备份（root 版）

给已 root 的安卓手机用的相册实时备份。新拍的照片、新存的图和视频几分钟内自动备份到 `/data/photo_backup`。只有 root 能访问这个目录，系统相册和媒体库都读不到，**相册里永远不会出现两份**。

## 它做什么

**实时同步**
- 常驻前台服务监听媒体库，新增照片视频几分钟内备份，开机自动启动
- **延迟备份**（默认 3 分钟，可调）：新图出现后先等一会儿，截完图马上删的那种不会进备份
- 录像会等文件写完再备份（大小和修改时间稳定后才复制）
- 不压缩：原文件原样复制，修改时间原样保留
- 每个文件复制后比对 SHA-256 校验值，对上才算备份成功
- **去重**：内容完全相同的文件只存一份（转发后多次保存的图不重复占空间）

**删除倒计时**
- 相册里删掉一张，备份进入倒计时，到期自动删（默认 30 天，可调）
- 「待删除」页能看到所有在倒计时的文件，点「放回」就回到相册原位置，时间和删除前一样；也可以「全部放回」或「全部删除」（不等倒计时直接清空）

**整理乱文件夹**
- 列出所有放照片视频的文件夹，把散在乱文件夹里的图**移动**（不是复制）到干净的文件夹：相机、截图、录屏、微信、QQ、其他
- 可以逐个文件夹选归到哪，也可以「一键全部整理」（认不出来源的归到 Pictures/其他）
- 只动已经备份并校验过的文件；移动后核对修改时间，相册排序不变
- 旧文件夹里一个文件都不剩了才删
- 可开「自动整理」：微信、QQ 新建的乱文件夹定期自动归位

**排除与保护**
- 排除文件夹（表情包、App 缓存图），按最小文件大小、最小图片尺寸过滤小图标
- 空间保护：手机剩余空间低于设定值（默认 3 GB）时暂停备份并提醒
- 首次备份后自动核对媒体库里照片视频的数量，**数量变多立刻报警并停止同步**

**导出与还原**
- 导出到 U 盘或手机存储里的文件夹（再拷到电脑），目录 `相册备份导出/` 带 `.nomedia`，插着 U 盘时相册也不显示；增量导出，可选导出后清空手机上的暂存（只清校验通过的）
- 长期没导出会提醒（默认 30 天）
- 还原有三种：待删除里单个放回 / 本机整体还原（全部或按年）/ 从 U 盘或文件夹还原（换新手机、刷机后用）
- 还原时先比对校验值，手机上已有的跳过；放回后写回修改时间、刷新媒体库，最后核对数量和时间并给出报告
- 新手机还没 root 也能从 U 盘还原，只是写回时间要走系统接口，可靠性不如 root

**日常**
- 首页：胶片条显示最近备份的缩略图，以及已备份数量、占用空间、待删除数量、最近同步时间
- 日志页：出问题时能看到是哪个文件、为什么失败
- 深色、浅色两套配色，跟随系统

## 顺序为什么不会乱

带拍摄信息的照片视频，相册按文件内部的拍摄时间排序，这个时间本来就跟着文件走。没有拍摄信息的（截图、保存的网图），相册按修改时间排序，备份时原样保留、还原时写回。两样都保住，顺序就和原来一致。

## 备份目录结构

```
/data/photo_backup/
  .nomedia
  index.tsv                 清单：每个文件的拍摄时间、修改时间、原路径、校验值、删除倒计时
  files/2024/05/IMG_xxx.jpg 备份文件，按 年/月 存放
```

App 的数据库被清掉（清数据、重装）后，会从 `index.tsv` 自动找回索引。

> ⚠ 刷机或恢复出厂会清空 `/data`，手机上的备份也会一起没。刷机前一定先导出到 U 盘或电脑。

## 权限

需要 root（SukiSU / KernelSU / Magisk）。有 root 时 App 会自己授予媒体读取和通知权限，并把自己加入电池优化白名单，避免被 ColorOS 杀后台。只备份内置存储（`/storage/emulated/0`）里的照片视频，不碰 `Android/` 和隐藏目录。

## 构建

标准 Gradle 工程（Kotlin，纯 framework 控件，没有 AndroidX）。包名 `cn.rikka.album`，minSdk 29，target 34。

```bash
./gradlew assembleRelease
```

详细步骤和验收方法见 [构建说明（给muse）.md](构建说明（给muse）.md)。
